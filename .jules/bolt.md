## 2025-05-18 - Caching `hasSkill()` and `canonSkillKey()` Lookups with WeakMap
**Learning:** `hasSkill(p, skillName)` is invoked hundreds of times during every match simulation across decisions, duels, transitions, shots, passes, and stamina decay. Previously, each check performed `normSkillKey(s)` (a string lowercasing and regex replacement) on every skill in the player's `skills` array sequentially in an O(N) linear scan. By caching canonical skill names in a string `Map` and caching a `Set` of canonical skills for each player's `expandedAttrs` object using a `WeakMap`, lookups become O(1) with zero garbage collector pressure or memory leaks.
**Action:** When working with frequently inspected player attributes or collections in hot simulation loops, use `WeakMap` keyed on the player's attribute object so cached lookups can be O(1) without mutating data structures or interfering with JSON serialization. Also note that `dist/app.js` and `app.js` must be synchronized directly alongside the source split modules under `data/`, `engine/`, etc., because `build.js` currently references missing split chunks.
